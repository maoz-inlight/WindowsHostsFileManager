# Preview profile colors

The color selector is available in **Open selected in isolation**, below the browser
choice. Choose a named preset, enter `#RRGGBB`, or use **Custom…**. An optional friendly
name and a color dot identify the profile in **More actions → Browser preview data**.
Select an existing profile there and click **Name & color…** to edit it.

The last browser selection is remembered across dialogs and app restarts. If that browser
is no longer installed, the dialog selects an available browser. The preference is stored
in `%LOCALAPPDATA%\HostsManager\preview-browser.txt`.

Appearance is saved with the existing browser/mapping/flags identity. Changing a name
or color does not create a different cookie/cache profile. Launch metadata updates
preserve appearance. Cancel leaves the profile unchanged.
Within the launch dialog, toggling flags or changing browser does not reset the current
name/color choice. Saved appearance is loaded once when opening the dialog.

For an existing browser profile, a color change requires closing processes for that
specific preview. Other profiles and ordinary browser windows can remain open. Use
**Close background preview** in Browser preview data after closing its windows; the app
asks before stopping this profile's remaining processes and refuses to stop visible
preview windows. Name-only changes do not modify browser preferences. A new profile
can receive its initial color before its browser starts. Only the app-owned profile's Default/Preferences file is patched;
unrelated settings are preserved and malformed or linked preferences are refused.

Chrome and Edge's autogenerated-theme preferences are internal
browser details, not a stable public API. The disposable Chrome 153 / Edge 153 prototype
retained the requested color in its persisted preferences; visual browser tint still
needs manual confirmation. Browser updates, policies and Incognito/InPrivate can override
or ignore the tint. Select **Browser default** to remove the app-selected color.

The active-preview banner includes an exact-color swatch and a color name/hex label.
Chrome now uses the same classic generated-theme path as Edge, with system-color
following and grayscale disabled. The earlier modern user-color path did not produce
the requested visible color in user testing; the user confirmed the replacement works on 24 September 2026.
Chrome still derives light/dark shades from the seed; the browser frame is not promised
to be pixel-identical to the swatch. Existing colors migrate to these corrected settings
the next time their inactive profile is opened. Color and profile data remain unchanged.

Validation: 232 tests passed and the WPF build has no warnings/errors. Tests cover theme
data for both browsers, reset, input validation, metadata persistence, active-browser
refusal, exact profile process matching, an actual read-only Windows process query,
theme migration and malformed preference preservation. Multiple concurrent preview sessions
remain a separate change; the app still tracks one active preview at a time.

Manual checks:

1. Select a disposable mapping and open it in isolation. Choose a name and blue color.
2. Confirm the browser frame/tab bar is tinted. Close the browser and reopen the same
   mapping; confirm the selection, cookies and profile identity are retained.
3. In Browser preview data, select that profile and choose Name & color. Cancel an edit,
   then save a different color with this preview's processes closed. Leave a normal
   browser window open to confirm it does not block this operation. If the selected
   preview lingers in the background, use Close background preview and retry.
4. Repeat with Chrome and Edge, a custom color and Browser default. Do not expect private
   windows to use the same tint.
